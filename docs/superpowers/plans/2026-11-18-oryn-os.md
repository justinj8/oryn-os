# Oryn OS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Oryn OS, a multi-tenant AI agent operating system that runs fully offline via `make up` and demonstrates durable multi-agent workflows, approvals, tenant isolation and a live dashboard.

**Architecture:** FastAPI API + Temporal worker (Python package `oryn`) over Postgres (RLS + pgvector) and Redis. Temporal owns durable run state, retries, timers and approval waits; each agent step is a LangGraph loop inside one Temporal activity. LLM and connectors sit behind interfaces with offline (Replay/sandbox) defaults and env-switched real providers. React dashboard consumes REST + SSE.

**Tech Stack:** Python ≥3.12 (containers 3.12), uv, FastAPI 0.164, temporalio 1.36, langgraph 1.2, anthropic 2.10, mcp 2.3, SQLAlchemy 2.1 (async, asyncpg 0.32), Alembic 1.20, pgvector 0.5, redis 8.1, pydantic 2.14 / pydantic-settings 2.16, twilio 9.13, PyJWT 2.15, argon2-cffi 25.1, cryptography 50, sse-starlette 3.7, structlog 26, pytest 9 + pytest-asyncio 1.5, ruff, mypy. Frontend: pnpm, Vite 8, React 19, TypeScript, TanStack Query 5, React Router 7, Tailwind 4, Recharts 3, openapi-typescript, Vitest 5, Playwright 1.65.

**Spec:** `docs/superpowers/specs/2026-11-18-oryn-os-design.md`

## Global Constraints

- Product name in all copy: **Oryn OS**. Python package `oryn`. Repo layout `backend/`, `frontend/`, `deploy/`, `scripts/`, `docs/`.
- Offline by default: with no env vars set, everything works. `LLM_PROVIDER=replay` default; `anthropic` only when `ANTHROPIC_API_KEY` is set. Twilio/SMTP real adapters only when their env vars are set; otherwise sandbox.
- The offline path must exercise the same graph, tool registry, approval policy and Temporal workflow as the real path (no bypasses).
- Every tenant-owned table has `tenant_id uuid not null` and an RLS policy `tenant_id = current_setting('app.tenant_id')::uuid`. Runtime DB role `oryn_app` has no `BYPASSRLS`. Only migrations/seed use `oryn_owner`.
- Roles ordered `viewer < operator < admin < owner`.
- Default Anthropic model: `claude-sonnet-5-5`. Offline embeddings: hashing embedder, dim **384**.
- Dashboard numbers come only from rows written by real runs; seed history is produced by running workflows.
- Compose stack target ≤ 4 GB RAM. Ports: web 5173, api 8000, temporal 7233, temporal-ui 8233, postgres 5432, redis 6379.
- Approval-gated side effects execute only in the `execute_action` activity with an idempotency key; never inside the agent loop.
- Demo credentials are local-only and documented in README; real secrets only via env.
- Commit at the end of every task (conventional commit messages).

## Review Focus

1. **Duplicate webhook delivery** (Twilio/email providers retry): the same inbound event twice → one run, one reply. Pinned in Task 16 (`test_duplicate_event_starts_one_run`) and Task 18 (`test_duplicate_twilio_message_sid_replies_once`).
2. **Double or late approval decisions** (double-click, two managers, decision after cancel/expiry): second decision → HTTP 409, action executed exactly once. Pinned in Task 15 (`test_approval_signal_after_completion_is_ignored`) and Task 16 (`test_second_decision_returns_409`).
3. **Agent that never finishes** (LLM keeps calling tools or loops on handoffs): bounded by `MAX_AGENT_ITERATIONS=8`, `MAX_HANDOFF_DEPTH=3` and per-agent $ budget → run escalates to a human instead of spinning. Pinned in Task 11 (`test_iteration_cap_escalates`, `test_budget_cap_escalates`) and Task 15 (`test_handoff_depth_cap`).
4. **NL builder given vague/unsupported/empty text**: returns warnings and `definition=None` or a partial draft flagged invalid; saving an invalid draft → 422, never a silently truncated workflow. Pinned in Task 20 (`test_unknown_phrase_becomes_warning`, `test_empty_text_returns_error`, `test_save_invalid_draft_rejected`).
5. **Cross-tenant access via request parameters** (user of tenant A sends `X-Tenant-Id` of B, fetches B's run by id, or opens B's SSE stream): 403/404, never data. Pinned in Task 3 (`test_foreign_tenant_header_forbidden`), Task 13 (`test_sse_rejects_foreign_tenant`), Task 16 (`test_get_foreign_run_404`).

### Task 5: Connector interfaces, error classification, fault injection, sandbox implementations

**Files:**

**Interfaces:**
- `errors.py`: `ConnectorError(Exception)` with `.provider`, `.status_code: int|None`; subclasses `RetryableConnectorError`, `NonRetryableConnectorError`. **Decision function** `classify_error(exc: BaseException) -> ErrorClass` where `ErrorClass(StrEnum) = retryable|non_retryable|rate_limited`. Rules: explicit subclasses win; `status_code` 429 → `rate_limited`; 408/5xx/`TimeoutError`/`ConnectionError`/`httpx.TransportError` → `retryable`; other 4xx/`ValueError`/`pydantic.ValidationError` → `non_retryable`; unknown → `retryable` (safe to retry because side effects are idempotent). Docstring explains why unknown defaults to retryable.
- `base.py` Protocols (all methods async, take `idempotency_key: str|None` where side-effecting):

  - `Billing`: `create_invoice(contact_id, amount_usd, idempotency_key) -> InvoiceDTO`, `list_overdue() -> list[InvoiceDTO]`, `issue_refund(invoice_id, amount_usd, idempotency_key) -> InvoiceDTO`.

  - `Database`: `query(sql: str, params: dict, limit: int=200) -> QueryResult` (read-only: single statement starting with `select`/`with`, executed in a `READ ONLY` transaction).
